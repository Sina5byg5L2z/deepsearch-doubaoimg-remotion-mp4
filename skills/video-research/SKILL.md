# 阶段 1 · 深度调研

> 输入：视频选题 + 用户边界（对象/地域/时间）｜ 产出：`research/FINAL_调研报告.md` + 事实卡片 + 校验记录 ｜ 依赖：无（本 skill 自包含，可独立使用）。

文案里每一个事实都必须能追溯到一张事实卡片。

**规则分级**：[必须] = 跳过即事实事故或方向报废；[建议] = 技艺增强，按调研规模裁剪。
**规模裁剪**：单事实快查（几百字结论够用）→ 走「8 步法」压缩版（拆解→卡片→校验，跳过 Issue Tree
细则与成稿技艺）；完整专题（5 分钟以上成片的底稿）→ 全流程。

## 任务规模分档

| 档位 | 判断 | 流程 |
|---|---|---|
| 快查 | 单一事实/数据点，主线程 3–5 次搜索能定论 | 主线程直接查 + 事实卡片，可省独立校验 |
| 标准专题 | 需要多维度交叉、多来源验证 | 8 步法全流程，重活下沉子 Agent |
| 因果解释 | 「为什么 X 没有成为 Y」类 | 先走方向述职，再按标准专题执行 |

## 子 Agent 分工（[必须]，上下文纪律）

调研是最烧上下文的阶段——原始搜索结果、网页正文动辄几十 KB，**严禁直接堆进主线程**：

- **按子问题拆子 Agent 并行跑**：社区挖掘、专名回查、数据交叉验证这类体力活全部下沉。
- **提示词必须自包含**：主题与边界、资料分层要求（L1>L2>L3>L4）、输出格式
  （事实卡片：内容 + 出处 URL + 确定性层级）、**读写文件路径**
  （原始资料写 `research/raw/<子问题ID>.md`，事实卡片追加 `research/02_事实卡片.md`）。
  子 Agent 看不到主对话，一切靠提示词和文件。
- **返回值只有两样**：≤200 字结论摘要 + 产出文件路径。主线程汇总时**只读事实卡片，不读原文**。
- **扩搜不自己上**：主线程发现盲区（触发「比如 X、Y = 全集指令」规则时），派**新的子 Agent** 去穷举。
- **校验天然是子 Agent**：产出者 ≠ 审查者；把事实卡片与推导过程文件路径交给校验 Agent。

主线程在调研阶段只增长「决策与结论」，不增长「原始资料」。

## 问题类型决定研究方向（[必须]：因果解释型必须先述职）

动笔前先判断：用户问的是「是什么」、「为什么」，还是「怎么办」？

- **「为什么 X 没有成为 Y」= 因果解释型**：差距本身是提问者已接受的前提，数据只用来一句话钉死差距；
  **调研主体是差距的生产机制**。禁止把「差距的度量」当调研主体（罗列数据证明"确实不是 Y" = 答非所问）。
  框架：概念钉死 → 改写为「差距被什么生产出来」→ 多条因果链平行挖到不可再拆 →
  对照组（同赛道谁成了 Y，差异点就是因果证据）→ 反事实 + 反向案例 → 前因后果闭环。
- **[必须] 方向述职**：因果解释型在 Step 1 完成后、大规模搜索前，主线程用 5 行以内向用户说明
  拟回答的核心问题、几条因果链、对照组选谁，确认后再派子 Agent——方向跑偏 = 全部白跑。
  快查型与「是什么」型可跳过述职。

## 问题拆解（Issue Tree，[建议]）

完整规程见 [`references/issue-tree.md`](references/issue-tree.md)。要点：

- 根问题先改写到精确可判，再 MECE 拆第一层（2–4 个分支，同层一种切法，至少试两种切法再定）。
- 只切 2–3 层，切到「能挂上具体证据」的粒度；假设先行（每分支一句可证伪假设 + 「什么证据能杀死它」）。
- 80/20 排序，其余显式搁置。快查型可直接跳过本节。

## 成稿技艺（[建议]，决定报告质量的上限）

10 条技艺与报告结构模板见 [`references/report-craft.md`](references/report-craft.md)，
写作范本两份：
- [`references/exemplar-调研报告-radwimps.md`](references/exemplar-调研报告-radwimps.md)——多轮调教后定稿的完整案例；
- [`references/exemplar-调研报告-bump.md`](references/exemplar-调研报告-bump.md)——**初次交付即按十维度清单一次到位**的范本（十二章节，对照姊妹报告逐章对齐，含两份范本互引的镜像命题写法）。
标准专题建议逐条对照；快查型不需要。

## 分析框架（[必须]：初次交付即满维度——十维度清单）

分析框架不是拍脑袋列 3 条，而是**对照十维度清单逐项自查**——缺哪个维度就先补哪个维度的证据，补完才写报告。用户点名的维度只是起点，不是全集；等用户点名再补 = 懒散交付（2026-10-14 通牒级规则）。

| # | 维度 | 要回答的问题 |
|---|---|---|
| 1 | 数据轨迹 | 关键指标（销量/播放/规模）的完整时间线，峰值→现在的每一级台阶 |
| 2 | 本体技法 | 作品/产品/文本本身怎么做的：写法、技法、结构与同类的差异 |
| 3 | 演变与受众分化 | 风格/策略怎么变的；老粉/新粉各喜欢什么、为什么分化 |
| 4 | 时代主流对照 | 按分期裁决「创新/另类/开创/跟进」，每期主流图景要有出处 |
| 5 | 同代/同业对照组 | 谁成了目标状态、谁同样没成——对照组是因果证据 |
| 6 | 地位与影响谱系 | 影响谁（本人原话+行为证据＞礼节性名单）、业内认可、制度奖项；记录反向案例（影响半径的边界） |
| 7 | 受众与粉丝文化 | 听众/用户是谁、怎么进来、怎么固化、跨代穿透口径 |
| 8 | 组织与运营 | 事务所/公司体量、成员变动、单核依赖、产出节奏 |
| 9 | 海外/跨域维度 | 出不出海、以什么形态影响域外 |
| 10 | 完整因果时间线 | 前因后果闭环，每环可回溯到事实卡片编号 |

- 用户意见（哪怕一句抱怨）= 同类问题的**全集指令**：先自己穷举该意见覆盖的所有方面再动手。
- 框架在 Step 4 定稿后禁止临场加维度；但十维度自查发现的缺口属于「框架没定稿」，回炉 Step 3 补证据，不算违规。
- 有姊妹报告时，新报告的广度与深度**不得低于姊妹篇**，交付前逐章对齐。

## 独立校验（[必须]，每轮新增内容都校验）

- Step 7 不是只跑一次：**每一轮新增的事实卡片组与推导，写入报告前都必须过独立校验 Agent**（数据抽查 + 逻辑审查[确定性升级/单点跳全称] + 遗漏检查）。
- **校验员点名的遗漏维度必须当场闭合**：派新子 Agent 补证 → 补卡片 → 复校；禁止写成「未展开项」留给下一轮。
- 「未展开项/边界记录」只允许写**确无证据的负结果**（如某引语两轮检索无果），不允许写「没来得及查」。
- 校验发现的修正**只进审计档案**（如 `05_校验记录.md`）：正文必须是第一次就写对的干净事实，禁止在报告里留「校验注：已改为…」式补丁。

## 来源甄别与转述纪律（[必须]，2026-10-14 增补）

- **AI 伪源甄别**：遇到可疑 wiki 类站点先交叉验证——成员名张冠李戴、同一页面自相矛盾（既说已婚又说未婚）、乐队史与公认事实冲突 = AI 生成站，**整站弃用**，并在校验记录中留甄别记录。维基镜像只作交叉验证，不作独立证据。
- **转述来源降级**：「带起 XX 风潮」「公认 XX」这类中文百科转述一律按 L4 社区观察级使用，不得当 [已确认] 引用；玩家/粉丝研究站的考据（如曲目调弦表）标注「考据级」，区别于访谈原话。
- **用户提供的数据**：如实标注来源与采集时点，只作偏好分布类证据使用，不外推全体；表中每个分节/每列都要扫全（分节结构漏读一列 = 漏一份榜单）。
- **估算值显式标注**（如 BSA 估算销量「只示趋势不示精确」），不与精确值混排。

## 8 步法

1. **问题拆解**：判问题类型（快查/标准/因果解释），按需走 Issue Tree 拆成 2–4 个子问题，
   明确边界（对象/地域/时间）。→ `00`
2. **资料分层锁定**：官方源定向搜索 → 官方页面直接验证 → 社区声音挖掘。→ `01`
3. **事实卡片**：每条事实一张卡（内容 + 出处 URL + 确定性层级）。→ `02`
4. **分析框架**：按选题类型定固定维度，禁止临场加维度。→ `03`
5. **参照物对齐**：对比各方定义稳定、无歧义。
6. **推导链**：显式写「事实 → 对照 → 结论」，结论不得悄悄升级确定性。→ `04`
7. **独立校验（[必须]，每轮新增内容都校验，见上节）**：启动独立子 Agent 复核事实卡片与推导，抽查 3–5 个核心数据点
   （给它文件路径，不让它听主线程转述）。快查型可由主线程自校替代。→ `05`
8. **用例验证 + 可交付化**：找一个典型场景验证结论；产出「一句话总结 + 结构化章节 + 证据链接」。→ `FINAL`

## 资料分层

| 层级 | 类型 | 可信度 |
|---|---|---|
| L1 | 官方文档、论文、规范、官方曲单/官网 | ✅ 高 |
| L2 | 官方博客、访谈实录、白皮书 | ✅ 高 |
| L3 | 权威媒体、专家解读 | ⚠️ 中（需交叉验证） |
| L4 | 社区讨论、个人博客、论坛 | ❓ 低（只作线索） |

## 事实纪律（[必须]，血泪教训）

### 专名零容忍
- 专有名词（人名/歌名/机构名/事件名，尤其外文译名）**必须回查原语逐字源**
  （官网/官方曲单/官方资料库），禁止机器翻译腔直接转写。
  典型翻车：日文歌名被机翻成另一个"听起来像"的名字。
- **宁可标注「未考证」也不写出未经核实的专名**；引语必须逐字核对来源。

### 三层确定性标注
| 层级 | 含义 | 标注 |
|---|---|---|
| 已确认 | 一手来源证实已发生 | `[已确认]` |
| 官方理由 | 执行方/当事方的解释动机 | `[官方理由]` |
| 理论风险 | 技术上可能但未被证实 | `[理论风险]` |

「X 在技术上可能」≠「X 已经发生」。成片文案描述后果时只能用「已确认」。

### 证伪完整性
- 下否定结论前，先验证**假设的完整表述**（时间/范围/程度限定词）。
  反例：查"现在在不在架"就断言"从未上架"——实际是后来才解禁的。
- 「调研对象说『比如 X、Y』」时，「比如」= 举例不是全集：必须把 X、Y 所属的**整个类别**排查完。

### 边界守恒
- 每条资料问「它能回答哪个子问题」，答不上就删。调研的目标是**回答问题**，不是展示知识面。

`FINAL_调研报告.md`：摘要（一句话结论）+ 按分析框架的结构化章节 + 每个关键事实附出处链接。
