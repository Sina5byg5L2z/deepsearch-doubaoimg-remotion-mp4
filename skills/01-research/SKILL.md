# 阶段 1 · 深度调研（8 步法 + 事实纪律）

视频的说服力全部来自这一步。**文案里每一个事实都必须能追溯到这里的某张事实卡片。**

## 子 Agent 分工（上下文纪律，最高优先级）

调研是整条流水线里最烧上下文的阶段——原始搜索结果、网页正文动辄几十 KB，
**严禁直接堆进主线程**。分工模式：

- **按子问题拆子 Agent 并行跑**：Step 1 拆出的每个子问题派一个调研子 Agent
  （L4 社区挖掘、专名回查、数据交叉验证这类体力活全部下沉）。
- **提示词必须自包含**：主题与边界、资料分层要求（L1>L2>L3>L4）、输出格式
  （事实卡片：内容 + 出处 URL + 确定性层级）、**读写文件路径**
  （原始资料写 `research/raw/<子问题ID>.md`，事实卡片追加 `research/02_事实卡片.md`）。
  子 Agent 看不到主对话，一切靠提示词和文件。
- **返回值只有两样**：≤200 字结论摘要 + 产出文件路径。主线程汇总时**只读事实卡片，
  不读原文**——需要核对时按卡片里的出处链接定点去查。
- **扩搜不自己上**：主线程发现盲区（触发「比如 X、Y = 全集指令」规则时），
  派**新的子 Agent** 去穷举，不要在主线程连环搜索。
- **校验天然是子 Agent**：Step 7 的独立校验本来就要求产出者 ≠ 审查者，
  把 `02_事实卡片.md` 和 `04_推导过程.md` 路径交给校验 Agent，让它自己读文件。

主线程在调研阶段应该只增长「决策与结论」，不增长「原始资料」。

## 问题类型决定研究方向（方向错了全白跑，BLOCKING）

动笔前先回答：用户问的是「是什么」、「为什么」，还是「怎么办」？

- **「为什么 X 没有成为 Y」= 因果解释型，不是度量型**：
  - 差距本身是提问者已接受的前提，数据只用来一句话钉死差距；**调研主体是差距的生产机制**。
  - 禁止把「差距的度量」当调研主体——罗列数据证明「确实不是 Y」= 答非所问，方向从第一步就错了。
- **因果解释型调研框架**：
  1. **概念钉死**：Y 在该语境由什么构成？X 与 Y 的差距具体是哪几项？（一段话，数据只在这里出现）
  2. **改写核心问题**：「差距是被什么生产出来的」——主动选择 / 文本结构限制 / 时代窗口错位，各占多少权重？
  3. **多条因果链平行**：组织结构、产品文本特性、媒介姿态、时代窗口、受众结构……
     每条链挖到不可再拆（底层动机、行业逻辑），最后合成「顶流条件缺了哪几个、缺是选择还是限制」。
  4. **对照组**：同赛道谁成了 Y？他们做了什么 X 没做的选择——**差异点就是因果证据**。
  5. **反事实 + 反向案例**：照对照组做会不会成（切分选择与限制的责任）；有没有 X 主动拒绝成 Y 的
     证据（有则答案的一半是「选择」而非「失败」，问题性质改变）。
  6. **前因后果闭环**：起因如何塑造选择，结果又反过来给了 X 什么（非 Y 的位置换到了什么）。
- **方向述职（BLOCKING）**：Step 1 完成后、大规模搜索前，主线程用 5 行以内向用户说明：
  拟回答的核心问题、几条因果链、对照组选谁。用户确认或纠正后再派子 Agent——方向跑偏 = 全部白跑。

## 资料分层

| 层级 | 类型 | 可信度 |
|---|---|---|
| L1 | 官方文档、论文、规范、官方曲单/官网 | ✅ 高 |
| L2 | 官方博客、访谈实录、白皮书 | ✅ 高 |
| L3 | 权威媒体、专家解读 | ⚠️ 中（需交叉验证） |
| L4 | 社区讨论、个人博客、论坛 | ❓ 低（只作线索） |

## 8 步法

1. **问题拆解**：先判问题类型（是什么/为什么/怎么办——「为什么」走上面的因果解释型框架），
   再拆成 2–4 个子问题，明确边界（对象/地域/时间）。→ `00`
2. **资料分层锁定**：官方源定向搜索 → 官方页面直接验证 → 社区声音挖掘。→ `01`
3. **事实卡片**：每条事实一张卡（内容 + 出处 URL + 确定性层级）。→ `02`
4. **分析框架**：按选题类型定固定维度，禁止临场加维度。→ `03`
5. **参照物对齐**：对比各方定义稳定、无歧义。
6. **推导链**：显式写「事实 → 对照 → 结论」，结论不得悄悄升级确定性。→ `04`
7. **独立校验（BLOCKING）**：启动独立子 Agent 复核事实卡片与推导，抽查 3–5 个核心数据点（给它文件路径，不让它听主线程转述）。→ `05.5`
8. **用例验证 + 可交付化**：找一个典型场景验证结论；产出「一句话总结 + 结构化章节 + 证据链接」。→ `FINAL`

## 事实纪律（血泪教训，最高优先级）

### 专名零容忍
- 专有名词（人名/歌名/机构名/事件名，尤其外文译名）**必须回查原语逐字源**
  （官网/官方曲单/官方资料库），禁止机器翻译腔直接转写。
  典型翻车：日文歌名被机翻成另一个"听起来像"的名字。
- **宁可标注「未考证」也不写出未经核实的专名**；引语必须逐字核对来源。

### 三层确定性标注
| 层级 | 含义 | 标注 |
|---|---|---|
| 已确认 | 一手来源证实已发生 | `[已确认]` |
| 官方理由 | 执行方/当事方的解释动机 | `[官方理由]` |
| 理论风险 | 技术上可能但未被证实 | `[理论风险]` |

「X 在技术上可能」≠「X 已经发生」。成片文案描述后果时只能用「已确认」。

### 证伪完整性
- 下否定结论前，先验证**假设的完整表述**（时间/范围/程度限定词）。
  反例：查"现在在不在架"就断言"从未上架"——实际是后来才解禁的。
- 「用户/调研对象说『比如 X、Y』」时，「比如」= 举例不是全集：
  必须把 X、Y 所属的**整个类别**排查完，只查被点名的两个算偷懒。

### 边界守恒
- 每条资料问「它能回答哪个子问题」，答不上就删。
- 调研的目标是**回答问题**，不是展示知识面。
