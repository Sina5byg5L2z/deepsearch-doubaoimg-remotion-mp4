# 阶段 2 · 文案与分镜

> 输入：阶段 1 的 `FINAL_调研报告.md` + Step 0 已定稿的风格 ｜ 产出：`视频文案.md`、`分镜表.md`、`subs/*.json`、`prompts.txt`、`发布信息包.md` ｜ 依赖：[`remotion-film`](../remotion-film/SKILL.md) 的风格样板页（Step 0 必用）。

## 前置条件（BLOCKING）

- **Step 0 风格已确定**：用户手动指定，或「AI 自动匹配」模式下调研结束时已宣布（风格 + 理由）。
  （样板页 `../remotion-film/assets/style-samples.html`）
  文案的幕结构、提示词前缀都依赖风格；没确定风格就动笔，返工风险全在下游。
- 文案口播气质也要匹配风格：像素/复古电视适合冷静叙事腔，手绘绘本适合温和讲述腔，
  自由发挥适合快节奏强观点腔——开场 3 秒的钩子写法随风格变。

## 交付物（全部落在 `<workspace>/`）

| 文件 | 内容 | 下游消费者 |
|---|---|---|
| `视频文案.md` | 逻辑大纲（一句话主线 + 幕级论证链 + 八项自检）+ 分幕口播文案 | 人审 + TTS |
| `分镜表.md` | 镜号/时长/画面事件/插画需求（镜头顺序必须与论证链一致） | 质量基线 |

| `发布信息包.md` | 标题/简介/标签/发布时段 | 最终交付 |

## 文案写作纪律

1. **只写阶段 1 事实卡片里有出处的内容**；推测性内容在片中显式标注（结尾页固定：
   「推测性内容已在片中明确标注 · 如有错误或补充，欢迎在评论区指出」）。
   **专名（人名/歌名/乐队名）必须从事实卡片逐字复制粘贴，禁止凭记忆或音译重写**——
   调研侧查证的逐字源（含汉字写法如《会心の一撃》）在文案环节丢失 = 事故前移到下游。
   事实卡片里标 [社区观察]/[理论风险] 的内容，文案中不得写成事实断言。
2. **反 AI 味文风**：禁止「第一/第二/第三」列表腔；禁止空洞排比；
   用具体的事实、数字和场景说话；口语化但不过度网络梗。
3. **主线先行（BLOCKING，先于一切正文写作）**：动笔前必须先产出「逻辑大纲」并写进 `视频文案.md` 头部：
   - **一句话主线**：主语 + 核心结论 + 一句话理由。例：「X 能火二十年，靠的不是才华，而是它把 B 情绪做成了产品」。
     写不出一句话主线 = 调研没消化，回到阶段 1，禁止硬写。
   - **幕级论证链**：列出每幕的论点，并标注幕与幕之间的连接类型（因果 / 递进 / 转折 / 对比 / 排除他因）。
     **禁止并列堆砌**——幕与幕之间只有「还有…」「另外…」关系的就是散点流水账，必须重排成推进关系。
   - **每幕一句话小结**：每幕论点用一句大白话复述，全部连读一遍就是全片脉络。连读不通顺 = 链条断了，当场修。
4. **结构**：强钩子开场（3 秒内抛出悬念/反直觉事实）→ 2–8 幕正文（每幕一个论点，
   且每个论点必须直接推进主线；删掉后主线不受损的幕 = 冗余，删除或合并）
   → 收尾回扣钩子。总时长按目标定（5–8 分钟适合深度专题）。
5. **段落切分以论点为单位，不以画面为单位**：切分依据是「这一段推进了论证链的哪一步」；
   「每段能画成一张插画」是约束（画不出的段落要改写），**不是切分依据**——
   先有论点再有画面，画面服务论点。段落 ID 定为 s01、s02…（后续所有文件都用这个 ID 关联）。
6. **幕间衔接句强制**：每一幕的第一句必须接住上一幕结尾抛出的问题/悬念/未尽之处，
   不允许幕与幕之间硬切。观众「不知道在说什么」的体感，一半来自幕间无衔接。

## 文案工艺（写前选型，写后自检——不允许跳过）

### 钩子选型（开场 3 秒）

五种钩子任选其一，禁止默认平铺直叙开场：

| 类型 | 写法 | 适用 |
|---|---|---|
| 反直觉事实 | 用最反常识的数字/结论开场 | 调研里有惊人数据 |
| 悬念提问 | 抛出观众答不出的问题 | 机制/原理类 |
| 身份代入 | 「如果你是…」直接锁定人群 | 人物/决策类 |
| 冲突对比 | 两个极端画面/数字硬撞 | 对比叙事 |
| 利益前置 | 先讲清「看完你能得到什么」 | 教程/干货 |

选型流程：先查 `short-video-script-cn` 爆款结构库里同类题材的钩子模板（150+ 库），
再按本片风格的腔调改写。钩子内容必须有事实出处，**不得为抓人而编造**。

### 台词节奏（口播密度硬指标）

- 中文口播按 **4–4.5 字/秒** 估算；每段字数 ≈ 目标秒数 × 4.2，写完逐段核对。
- 单句 ≤ 20 字，长句必须拆；段落内短句优先，保证 TTS 断句自然。
- 每 30–40 秒必须有一个「信息高点」（新事实/新数字/转折），否则观众流失。

### 叙事骨架（一片只用一个，且必须落到逻辑大纲）

- **悬念驱动**：钩子 → 铺垫 → 反转 → 收尾回扣（揭秘/历史/考古）
- **问题驱动（PAS）**：痛点 → 放大 → 解决 → 展望（科普/工具）
- **递进驱动（AIDA）**：注意 → 兴趣 → 欲望 → 行动（种草/安利）

骨架只决定幕的排列模板；**幕与幕的推进关系以逻辑大纲里标注的连接类型为准**，
两者冲突时以主线为准调整幕序，不为套模板牺牲逻辑。

### 写完八项自检（全过才算完）

1. **主线**：只读文案（不看大纲）能否用一句话复述主线？复述不出 = 判「不知所云」，改稿
2. **论证链**：幕与幕均为因果/递进/转折/对比/排除他因关系，无并列堆砌；
   每幕删掉后主线受损（不受损 = 冗余幕，删/并）
3. **幕间衔接**：每幕第一句接住上一幕结尾，无硬切
4. **钩子**：3 秒内有悬念/反直觉，且内容有事实出处
5. **节奏**：每段字数÷目标秒数在 4–4.5 之间；无 >20 字长句
6. **高点密度**：每 30–40 秒一个信息高点
7. **反 AI 味**：无列表腔、无空洞排比、无 AI 高频词（深入/赋能/综上所述/值得一提的是）
8. **画面可画性 + 收尾**：每段都能画成一张具体插画（只含看得见的东西）；回扣钩子 + 固定免责文案

任何一项不过 → 改稿重检，不允许「先过再说」。自检结果连同**一句话主线与幕级论证链**
写进 `视频文案.md` 头部（八项 ✓/✗ 清单），作为用户审核文案时的参考；
用户反馈「逻辑乱/不知道在说什么」时，先对照第 1–3 项定位，再动笔改。

## 分镜表（渲染前质量基线）

```
| 镜号 | 时长 | 画面事件 | 台词要点 | 插画 |
|---|---|---|---|---|
| s01 | 8s | 钩子大字+老电视开机 | 「xxx凭什么…」 | 需要 |
```

- 每 1.5–3 秒一个视觉事件；单镜头 2–4 秒。
- 60 秒视频 ≥ 20 个镜头事件，写完自查。

## 插画提示词模板（写进 prompts.txt 的每一条）

```
固定前缀：手绘科普插画，米白色纸张背景，黑色钢笔简笔画线条，局部淡彩（浅蓝浅黄浅粉），
Q版漫画人物，构图简洁大量留白。
+ 本场景具体画面描述（只描述视觉元素，不含任何抽象概念）
固定后缀：画面中绝对不要出现任何文字、数字、字母。
```

- **画面里绝不出现文字**——AI 生图的文字必然乱码，文字全部由 Remotion 代码层叠加。
- 提示词只描述"看得见的东西"：人物在做什么、有哪些道具、光线氛围。
- 风格模板可整体替换（像素风/复古电视/水墨…见 [`remotion-film`](../remotion-film/SKILL.md) 的 12 种风格方法论：7 基础 + 5 开源衍生），
  但前缀后缀纪律不变。

## TTS 与时长表

- 逐段合成 TTS 后实测时长，输出 `durations.json`（`{"s01": 8.2, "s02": 11.7, ...}`）。
- **时长以解码实测为准**：WAV 头解析结果要用 `ffprobe -show_entries format=duration` 复核，
  两者不一致（坏头/VBR 封装）以 ffprobe 为准。时长错了，下游 timeline 与混音全错位。
- 同批 TTS 的首尾静音处理必须一致：要么全部不裁（留 TTS 原生静音），
  要么全部按同一参数裁（如 ffmpeg silenceremove）——混着来会逐段积累偏移。
- **字幕句级强制对齐（TTS 合成后必做）**：`subs/*.json` 里的 t 是按 4–4.5 字/秒估算的，
  与 TTS 实际语速存在句级偏差。用 [`scripts/align-subs.mjs`](scripts/align-subs.mjs)
  以音频静音间隙反推每句真实起点：
  `node align-subs.mjs --tts tts/ --subs subs/`（输出 `subs-aligned/`，
  格式不变 `[{t,text}]`，Remotion 侧零改动）。
  三级策略自动选择：区间==句数逐句 1:1（最准）→ 合并最小间隙 → 按字数分摊兜底。
  对齐后的 t 是实测值，字幕早出/晚出问题在此根治；跑完看每段 maxΔ，
  超过 1s 的段人工核对句数与停顿是否匹配。
- **timeline 的段落时长以 TTS 实测时长为准**，不是文案字数估算。
- 多段 TTS 音色漂移的根治：用 voiceclone（参考音频锁音色），或全片用同一预置音色。
